# Phase 5 单账号八维分析

日期：2026-11-03。对应 [开发顺序](product/DEVELOPMENT_PLAN.md) 第 7 节 Phase 5。

## 思路

模型的调用、结构校验、原文证据核对、复核门槛在后端已经存在（`library_analysis` + `structured_ai` + `analysis_worker`）。Phase 5 做两件事：

1. 把真实分析接进新工作台（笔记库旁边的「八维分析」标签），不再依赖旧页面。
2. 保证生成失败、数据缺失、未配置模型三种情况都不影响笔记库和导出。

## 页面与状态机

`/workspace` 顶部增加「笔记库 / 八维分析」切换。分析页按后端状态渲染：

| 状态 | 页面表现 |
|---|---|
| 未配置模型 | 提示「还没有配置模型」+ 去设置；笔记库不受影响 |
| idle | 目标输入框 + 费用确认勾选 + 生成按钮 |
| running | 当前阶段文案 + 刷新；可以切回笔记库继续筛选、导出 |
| ready | 优先结论、四段战略、8 个维度、3 个选题、复核与导出 |
| failed / stale | 失败原因或「笔记库已变化」+ 重试按钮；不遮挡笔记库 |
| 无数据维度 | 卡片直接写「这个维度本批数据不足，未做推测：未获取」 |

## 结果展示

- **优先结论**：`analysis.headline`，一句话说明这次先解决什么。
- **四段战略**：内容主线、可复用模型、增长路径、主要风险。
- **八维卡片**：维度名、状态（有依据 / 数据有限 / 未获取）、观察、解读、下一步、另一种解释、引用原句（标题或正文摘录）、该维度的边界说明。
- **3 个选题**：读者问题、2 个标题、开头、3–5 段大纲、测试与复盘指标、引用证据。
- **复核交付**：未确认只能预览；确认后开放 HTML/PDF 下载，与后端 `approve` 门槛一致。
- 界面语言保留「优先维度、下一步、复盘」这类业务词，不出现 schema、指纹等术语。

## 证据与边界

- 每条发现引用 1–4 条原句，后端校验必须是本批笔记的标题或正文摘录，伪造会被拒绝。
- 卡片底部保留该维度的边界句（例如「没有曝光和点击数据，不能证明标题带来了互动」）。
- 缺失数据不补数字：无数据维度直接 `unavailable`，界面写「未获取」。

## 失败隔离（已验证）

写入一条 `status=failed` 的分析状态后打开任务 #7：

- 分析页显示失败原因与「重试生成」
- 切回笔记库仍有 50 行数据，导出按钮可用
- 不会因为分析失败而阻塞筛选、分页或导出

## 界面验证用的示例报告（不调用模型）

`scripts/dev_seed_analysis.py --task 8` 会写一份带真实数字与真实原句的示例报告，用于没有模型 Key 时检查页面布局：

- `model` 字段标记为「示例数据（未调用模型）」，页面顶部会显示该标记。
- 标题、互动、标签来自真实数据集；文字是手写示例，不代表模型产出。
- 只在本地开发数据目录生效，不进入交付包。

## 验证结果（2026-11-03）

- `tests/browser/analysis-smoke.cjs`：**11/11 通过**，覆盖标签切换、优先结论、8 个维度、三种状态徽标、未获取卡片、3 个选题（6 个标题 + 大纲）、引用原句、复核点击、确认后状态、未配置模型提示。
- 失败隔离检查：失败原因显示、重试按钮、笔记库 50 行、导出可用，四项全部通过。
- Python 回归：**82 项通过**，其中 `test_library_analysis` 覆盖结构校验、伪造引用、重复标题、超时与鉴权错误；生成失败时只更新分析状态，不修改 dataset。
- 真实模型生成尚未在本轮执行：本轮用示例报告验证了界面与失败路径，真正调用会用你自己的 Key 和额度。

## 仍需人工验收

1. 用真实模型对 3 个账号各生成一次，检查结论是否回答「账号做什么、哪些内容值得继续、下周做什么」。
2. 检查生成费用与耗时是否符合预期（当前每次 1–2 次模型调用，20 篇以上分两段）。
3. 确认 HTML/PDF 下载在真实报告上分页正常。

## 已知限制

1. 没有做流式输出，页面只能看到阶段文案。
2. 生成期间切换任务会中断轮询（后端任务继续，可回来刷新查看）。
3. 目标文本 5–1200 字，过短会拒绝提交。
