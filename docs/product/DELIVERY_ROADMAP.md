# 后续变更与开发路线

## 1. 当前判断

当前产品已具备：

- 授权主页采集。
- 最多100篇详情。
- 28列数据与三种表格导出。
- 公开互动分析。
- AI账号诊断和3个选题。

当前主要缺口不是“AI不够强”，而是：

1. 研究库没有成为产品主入口。
2. 任务结果没有形成跨批次持续资产。
3. 飞书仍停留在导入文件，未形成工作台体验。
4. 单篇拆解没有独立结构。
5. 图文、视频、账号没有分层视图。
6. 失败、去重、增量更新不够可视化。

## 2. 开发原则

- 先采集与呈现，后AI。
- 先结构化字段，后长篇报告。
- 先单机可靠，后飞书自动同步。
- 先公开且可验证的指标，后复杂媒体分析。
- 每个阶段有独立可售卖结果，不一次铺满所有功能。
- 旧任务、旧数据和当前导出格式保持兼容。

## 3. 分阶段路线

### Phase 0：需求冻结与字段定义

目标：

- 确认研究库、账号库、图文库、视频库、拆解库、选题库、运行记录。
- 确认哪些字段来自采集、哪些由AI生成、哪些必须人工确认。
- 确认飞书直连是否作为首期售卖承诺。

验收：

- 形成可审核的数据字典。
- 每个字段有来源、类型、空值规则和更新规则。
- 未经确认不得开发UI。

### Phase 1：研究库主入口

目标：

- 新首页从“AI报告入口”改为“研究库”。
- 支持账号、图文、视频和采集状态视图。
- 列表与画廊切换，显示封面、标题、作者、互动、类型、来源。
- 跨任务检索与全局去重。
- 选择多条笔记执行导出或标记研究状态。

验收：

- 新用户能在30秒内理解“采了什么、能筛选什么、能导出什么”。
- 同一笔记在多个任务重复出现时只显示一个研究实体。
- 失败条目单独可见且可重试。
- 旧任务可以迁移到研究库。

### Phase 2：采纳入口与增量更新

目标：

- 保留当前主页扩展采集。
- 增加单条/批量公开链接输入。
- 增加“只采集新增内容”模式。
- 支持主页模式与链接模式的任务来源标记。
- 视频链接只读取可公开取得的数据。

验收：

- 链接去重准确。
- 部分失败不丢成功数据。
- 同一账号第二次采集能识别新增和重复。
- 无登录模式和登录模式边界清楚。

### Phase 3：飞书导入文件2.0

目标：

- 输出多表、预设字段、类型和视图说明。
- 提供账号库、原始库、图文拆解、视频拆解、选题库、运行记录。
- 每次输出Excel备份。
- 输出失败摘要和字段覆盖报告。

验收：

- 真实飞书多维表格成功导入。
- 日期、数字、多行文本、超链接类型正确。
- 字段缺失不显示为0。
- 导入后可筛选、分组和排序。

### Phase 4：单篇结构化拆解

目标：

- 单篇笔记可独立触发AI拆解。
- 输出固定字段，不生成难以比较的长段落。
- 每个判断带原文证据。
- AI失败不阻塞原始笔记库。
- 拆解结果可写入飞书。

验收：

- 相同字段在不同笔记间可比较。
- 无图片、无字幕、无正文时明确标记。
- 无虚构因果、粉丝画像和转化结果。
- 重复内容不重复消耗AI。

### Phase 5：直接同步飞书

目标：

- 配置用户自己的飞书授权。
- 选择 Base、数据表、字段映射。
- 新增、更新和跳过重复。
- 失败可见、可重试、可撤销本次连接。

验收：

- 无凭据泄露。
- 重复运行不产生重复行。
- 更新不覆盖人工修改字段。
- 飞书 API 失败不损坏本地研究库。

### Phase 6：账号对标与长期研究

目标：

- 账号卡片与横向对比。
- 多次采集的内容/主题/表现变化。
- 高表现样本与普通样本对照。
- AI账号报告按需生成。

验收：

- 能区分当前快照与历史变化。
- 能标注样本量、日期跨度和缺失数据。
- 不把公开互动变化当作涨粉或曝光。

### Phase 7：商品化交付

目标：

- 安装包、更新机制和使用手册。
- 授权与版本策略。
- 试用、标准、专业和服务型交付边界。
- 支持渠道和隐私说明。

验收：

- 新机器按手册可完成安装、采集、导入和卸载。
- 不携带模型Key、Cookie、任务数据。
- 核心流程一次完整验收通过。

## 4. 优先级建议

最先做：

1. 研究库主入口。
2. 飞书导入文件2.0。
3. 全局去重与运行记录。
4. 单篇拆解结构化字段。

暂缓：

- 复杂飞书 OAuth。
- 视频转写和图片视觉分析。
- 多账号协作。
- 自动发布、编辑或商业投放。
- 复杂会员系统。

原因：

- 前四项直接决定用户是否觉得“买到了可长期使用的数据资产”。
- 后几项成本和平台风险高，不能替代核心体验。

## 5. UI参考输入流程

后续如果提供新的UI参考图，应按以下信息记录：

1. 图片属于工作台、列表、详情、导出、报告还是商品页。
2. 需要借鉴的是布局、颜色、字体、信息密度还是交互。
3. 哪些元素不能复制。
4. 适配桌面还是移动端。
5. 目标用户看到后的第一印象。
6. 是否需要保留当前品牌识别。

在UI方案确认前，不进行大规模视觉重构。

## 6. 总体验收

只有在以下条件全部满足后，才视为核心商品可交付：

1. 新主页/链接能够稳定进入研究库。
2. 图文、视频、账号有清晰视图。
3. 去重、失败、来源和更新时间可审计。
4. Excel和飞书文件字段完整。
5. 真实飞书导入成功。
6. AI为可选操作，失败不影响原始数据。
7. 用户无需理解模型结构或技术日志即可完成任务。
8. 安装、升级和卸载不会破坏历史研究资产。
