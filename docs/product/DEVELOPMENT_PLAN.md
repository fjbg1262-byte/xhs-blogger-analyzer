# 开发顺序

## 1. 开发原则

1. 先做前端 Demo，确认页面和操作方式，再接真实数据。
2. 先完成采集、笔记库和飞书交付，再做AI。
3. 先做单账号八维分析，再做多账号对比。
4. 每阶段都形成可点击、可展示的结果。
5. 不一次性重写现有采集器和旧功能。

## 2. Phase 0：PRD确认

目标：

- 确认产品只保留“采集、飞书交付、账号八维分析”三条主线。
- 确认页面文案直接说明数据和下一步动作。
- 确认首期以Windows本地工具为交付形式。

产出：

- [PRD](PRD.md)。
- [竞品截图](competitor-screenshots/)。

进入下一阶段条件：

- 页面结构、八维名称和飞书表结构确认。
- 明确首期哪些功能只做Demo，哪些接真实数据。

## 3. Phase 1：纯前端Demo

这是第一步，也是后续UI基础。

### 使用假数据完成

- 首页。
- 采集任务进度页。
- 笔记库列表。
- 笔记库封面视图。
- 单篇详情侧栏。
- 飞书交付页。
- 账号八维分析页。
- 双账号对比页。
- 采集记录页。

### Demo要求

- 可以点击完成完整流程。
- 支持表格/封面切换。
- 支持图文/视频分类筛选。
- 有真实产品感的封面图、标题、互动和链接占位数据。
- 支持桌面宽度和非超宽笔记本。
- 不写大段说明。

### 验收

- 不看说明书，能猜出从哪里开始。
- 从首页到飞书下载不超过4次点击。
- 从笔记库到单账号分析不超过2次点击。
- 选择两个账号能打开对比页。

验收状态（2026-11-01）：已通过。功能验收 33/33、点击验收 34/34，明细与复跑方式见 [Phase 1 验收记录](../PHASE1_ACCEPTANCE.md)。

## 4. Phase 2：接现有真实采集

### 目标

保留当前插件和采集器，将结果接到新笔记库Demo。

### 内容

- 插件启动采集。
- 任务进度。
- 图文/视频数据。
- 正文、标签、互动、封面和来源链接。
- 未完成原因。
- 停止后保留下载。

### 验收

- 用真实账号采集至少20篇。
- 100篇任务能完成或明确显示未完成原因。
- 页面不因个别笔记缺字段而空白。
- 刷新页面后任务仍能恢复显示。

## 5. Phase 3：笔记库与导出

### 目标

把采集结果做成日常可用的数据工具。

### 内容

- 全账号与单账号筛选。
- 表格/封面切换。
- 图文/视频筛选。
- 搜索、排序、日期筛选。
- 多条选择。
- Excel、CSV、飞书导入包。
- 每次任务生成备份。

### 验收

- 100篇笔记筛选和排序无明显卡顿。
- 导出条数与页面筛选一致。
- 正文、链接、标签和日期在Excel中正确。
- 飞书导入包字段干净，无说明行混在数据中。

## 6. Phase 4：飞书导入2.0

### 目标

让用户第一次导入就能看到清楚的账号、图文、视频和选题工作表。

### 内容

- 账号总览表。
- 全部笔记表。
- 图文表。
- 视频表。
- 选题表。
- 采集记录表。
- 飞书导入说明。
- Excel备份。

### 验收

- 真实飞书多维表格导入成功。
- 日期、数字、多行文本和链接类型正确。
- 导入后能按账号、类型和互动排序。
- 用户能在3步内完成导入。

## 7. Phase 5：单账号八维分析

### 目标

在已有真实数据上生成用户能读懂、能直接使用的八维分析。

### 内容

- 账号定位。
- 内容方向。
- 选题结构。
- 标题与封面。
- 互动表现。
- 发布节奏。
- 标签与搜索。
- 下一步建议。

### 要求

- 分析结果以卡片、表格和短结论呈现。
- 3个选题包含标题、开头和正文大纲。
- 数据缺失时直接写“未获取”，不补数字。
- AI生成失败时，笔记库和导出仍保持可用。
- 用户界面不出现难懂的报告术语。

### 验收

- 用3个真实账号分别生成八维结果。
- 结果能回答账号做什么、哪些内容更值得继续、下周做什么。
- 用户不需要读附件或脚注才能理解。

## 8. Phase 6：多账号对比

### 目标

把两个账号放在同一套八维中比较。

### 内容

- 选择2至5个账号。
- 生成同维度横向表。
- 输出值得继续的方向。
- 输出不建议照搬的做法。
- 生成一周内容计划。

### 验收

- 对比内容不只是重复两个单账号结论。
- 能明确指出相同点、差异和下一步动作。
- 数据量差异过大时页面有直接提示。

## 9. Phase 7：飞书直接同步

### 目标

从“下载导入文件”升级到“选择飞书表格后写入”。

### 内容

- 飞书账号连接。
- Base和表选择。
- 字段对应。
- 首次写入。
- 后续只添加新笔记。
- 更新互动数据。
- 跳过重复笔记。

### 验收

- 重复运行不会产生重复行。
- 用户可以关闭同步并删除连接配置。
- 飞书写入失败不损坏本地数据。
- 不导出登录凭证和模型密钥。

## 10. Phase 8：商品化

### 内容

- 安装包与使用手册。
- 版本更新。
- 试用和正式版限制。
- 飞书配置说明。
- 示例数据。
- 客服和退款说明。

### 验收

- 全新电脑按手册可以完成安装和第一次采集。
- 从采集到飞书导入有一次完整演示。
- 不携带任何本机账号、运行数据和密钥。

## 11. 优先开发清单

第一批只做：

1. 静态前端Demo。
2. 笔记库表格和封面视图。
3. 飞书交付页。
4. 单账号八维结果页。
5. 双账号对比页。

第二批：

1. 接真实采集。
2. 导出Excel/CSV/飞书包。
3. 八维分析接真实数据。

第三批：

1. 全局筛选。
2. 多任务去重。
3. 飞书直接同步。
4. 安装和售卖流程。

## 12. 后续UI图片的处理方式

你后续提供UI参考图时，先记录以下信息，再决定是否改Demo：

- 参考的是整个页面还是某个组件。
- 参考布局、颜色、字体，还是交互。
- 页面属于首页、笔记库、账号分析、对比还是飞书页。
- 需要保留还是舍弃的内容。
- 是否需要适配手机。

确认后才调整Demo，避免一边开发一边反复改方向。
